# daily-feedbox

The daily Feedbox brief. Markdown in, static site out.

## How it works

`briefs/YYYY-MM-DD.md` is the source of truth. `build.js` renders every one of
them into `dist/`:

- `YYYY-MM-DD.html` — one page per brief, so a link sent to someone keeps working
- `index.html` — a copy of the newest day
- `archive.html` — every brief, oldest to newest
- `_headers` — Netlify cache rules; the front page and archive revalidate, dated pages cache for 10 minutes

Each page ends with a footer listing the seven most recent briefs plus a link to
the full archive. That list is generated at build time, so adding a day no longer
means rewriting yesterday's page.

Nothing is pruned. Every markdown file in `briefs/` gets a page, and the archive
only grows.

## Adding a brief

Drop the markdown in `briefs/` named for its date and push. Netlify rebuilds.

```
briefs/2026-10-02.md
```

The date in the filename sets the page URL and the dateline, so it has to match
the brief's own `# Feedbox brief — …` heading.

## Building locally

No dependencies, so there is nothing to install.

```
pnpm build          # or: node build.js
npx serve dist      # to look at it
```

Options: `--src briefs`, `--out dist`, `--recent 7`.

## The markdown subset

`build.js` understands only what the brief uses, and treats anything else as a
build failure rather than passing it through:

| markdown | becomes |
| --- | --- |
| `# Title` | `h1` (one only; a trailing date moves to the dateline) |
| `## Section` | `h2` |
| `1. item` | `ol.points > li` |
| `- item` | `ul > li` |
| paragraph | `p` |
| `**bold**`, `` `code` `` | `strong`, `code` |
| `[text][ref]`, `[text][]` | `a`, resolved against the definitions at the foot |
| `[ref]: https://…` | link definition, stripped from the output |

So the build fails on an unresolved or unused link definition, an inline
`[text](url)` link, an `h3`, a second `h1`, a blockquote, a code fence, a table,
a leftover Provenance section, and unclosed bold. A broken brief fails the deploy
instead of publishing badly.

## Relationship to the skill

These pages are generated by the `feedbox-brief` skill, which writes the
markdown, checks it, and renders its own copy with `render.py` for delivery in
chat. `build.js` is a port of that renderer plus the site assembly that used to
live in `publish.py` — the two produce byte-identical `<article>` markup, and
they need to stay in step.

## Gaps

2026-09-25 has no brief. That day's run produced nothing, and the dump it would
have used was overwritten the following night. The build reports any such gap.
